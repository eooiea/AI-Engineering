# 📚 Git 커밋 컨벤션 상세 표준가이드 (Commit Convention Reference)

본 문서는 `commit-msg` 스킬이 참조하는 세부 규격 가이드라인입니다.

---

## 1. Type 선택 가이드

* **`feat`**: 사용자에게 새로운 가치가 전달되는 기능 구현
* **`fix`**: 올바르지 않던 동작을 올바르게 바로잡음
* **`refactor`**: 동작은 동일하지만 내부 가독성/성능/구조가 개선됨
* **`docs`**: 사용법, README, 주석 등 문서성 파일 변경
* **`style`**: 들여쓰기, 세미콜론, 줄바꿈 등 포맷팅 수정
* **`chore`**: `pip install`, `package.json`, `.gitignore` 수정
* **`test`**: 유닛 테스트, 통합 테스트 코드 작성

---

## 2. 좋은 커밋 메시지의 3대 원칙
1. **제목은 50자 이내로 명확하게 작성한다.**
2. **무엇을(What) 왜(Why) 변경했는지 본문에 상세히 적는다.**
3. **각 작업 영역별로 `-m` 플래그를 나눠 개별 세부 변경을 구분한다.**
