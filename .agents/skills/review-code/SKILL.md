# 코드 리뷰어 가이드라인 (Code Review Instructions)

이 지침은 사용자가 코드 리뷰 또는 코드 정적 검사를 요청할 때 작동하는 시스템 지침입니다. 에이전트는 코드 리뷰를 수행할 때 반드시 다음 항목들을 준수하여 결과를 보고해야 합니다.

## 📋 핵심 점검 대상
1. **가독성 및 네이밍 (Naming & Readability)**
   *   변수명, 함수명은 `snake_case`를 사용하는지 확인합니다.
   *   클래스명은 `PascalCase`를 지키고 있는지 검증합니다.
   *   직관적이지 않은 약어 사용을 줄이고 의미를 명확히 하고 있는지 확인합니다.

2. **문서화 (Documentation)**
   *   모든 파일 최상단에 모듈에 대한 짧은 요약이 명시되어 있는지 확인합니다.
   *   복잡한 함수나 클래스 정의 아래에 `docstring`이 적절히 들어가 있는지 검토합니다.

3. **안전성 및 예외 처리 (Safety & Exception Handling)**
   *   `try-except` 구문에서 광범위한 `except Exception:` 캐칭이 있는지 점검하고, 가급적 구체적인 Exception 종류를 캐칭하도록 권고합니다.
   *   에러 발생 시 디버깅이 가능하도록 로깅이나 적절한 에러 문구가 포함되었는지 확인합니다.

4. **성능 및 안티패턴 (Performance & Code Smell)**
   *   비효율적인 루프 중첩이나 중복 코드가 있는지 확인합니다.
   *   하드코딩된 설정값(API key, 경로 등)이 있는 경우 설정 파일이나 환경변수로 분리할 것을 가이드합니다.
